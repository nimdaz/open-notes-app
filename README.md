# Open Notes App

A small, self-hosted, mobile-first web app for plain text notes and
checklists, optionally sorted into groups. Everything is stored locally in a
SQLite database — no accounts, no cloud sync, no analytics.

**Version:** 0.0.4

## Features

- **Notes** are either plain text or a checklist, without any formatting. Each
  note has a title, an optional description, an optional group, and created /
  modified times. A markdown type is planned for a future release.
- **Notes list** with icon toggles to show or hide each note type, and a title
  search that filters as you type.
- **Full-page notes:** a note opens read-only and uses the whole screen. Checklist
  items can always be ticked and are saved immediately. Tap anywhere (or the
  pencil) to edit; the pencil becomes an eye to go back to reading. Edits are
  saved automatically when leaving edit mode, going back, or when the window
  becomes inactive, with a short "Saved" message at the top of the screen.
- **Note details:** a floating button at the bottom opens a panel with the type,
  created/modified times, and editable title, group and description.
- **Groups:** a note belongs to one group or none. Notes without a group are
  shown as **Unsorted**, which is always listed first; other groups are sorted
  alphabetically. Groups can have a description. Deleting a group moves its
  notes to Unsorted.
- **CSV export/import** on the Settings page backs up and restores all groups
  and notes in one file, and there is a "Remove All Data" option.

## Technical background

- **Backend:** Python, [Flask](https://flask.palletsprojects.com/), organized
  as blueprints per resource (notes, groups, settings).
- **Data:** [SQLAlchemy](https://www.sqlalchemy.org/) ORM over a SQLite file.
- **Templates:** [Jinja2](https://jinja.palletsprojects.com/), server-rendered.
- **Frontend:** [Pico CSS](https://picocss.com/) for styling and
  [htmx](https://htmx.org/) for the dynamic bits (note search, checklist
  toggling), both bundled in `app/static` — no build step, no JavaScript
  framework, no bundler. The note edit screen uses a few lines of inline JS.

## Installation

### Docker (recommended)

Using `docker-compose`:

```
git clone https://github.com/nimdaz/open-notes-app.git
cd open-notes-app
docker compose up -d
```

The app will be available at `http://localhost:5000`. Data is stored in
`./data` on the host, so it survives container restarts and rebuilds.

Without compose:

```
docker build -t open-notes-app .
docker run -d -p 5000:5000 -v "$(pwd)/data:/code/data" open-notes-app
```

Once published, the image is available as `ghcr.io/nimdaz/open-notes-app:latest`.

### Running locally with a virtual environment

Requires Python 3.10+.

```
git clone https://github.com/nimdaz/open-notes-app.git
cd open-notes-app
python -m venv .venv
source .venv/bin/activate    # on Windows: .venv\Scripts\activate
pip install -r requirements.txt
python run.py
```

Then open `http://localhost:5000`. By default the SQLite database is created
at `app/data/app.db`; set the `DATA_DIR` environment variable to change that.

> The built-in server (`python run.py`) is a development server. If you're
> exposing this beyond your own machine or home network, put it behind a
> proper WSGI server (e.g. gunicorn) and a reverse proxy.

## Releasing

Bump `APP_VERSION` in `app/version.py` (and the version line above) and push to
`main`. The GitHub Action publishes the image to `ghcr.io` tagged with that
version, `latest`, and the commit SHA.

## A note on how this was built

This app was built collaboratively with **Claude Sonnet 5.5** (Anthropic),
used interactively through a **free Claude.ai account**. Development was
iterative: each feature was specified in detail and generated by the model,
with a human guiding every step — so this is AI-assisted development, not
autonomous generation — but it hasn't had a professional security review or
extensive real-world testing. If you plan to run this somewhere more exposed
than your home network, review the code yourself first, particularly around
file upload handling (CSV import) and deployment configuration.
